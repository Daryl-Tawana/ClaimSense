# ClaimSense Journal #000 — Project Origin

**Date:** 17 August 2026

## Why am I building ClaimSense?

I am a second-year Actuarial Science student in Zimbabwe with an interest in programming, data science, machine learning and artificial intelligence.

I do not want to simply graduate with knowledge of these subjects.

I want to demonstrate that I can use them to solve real problems.

ClaimSense is being created as a long-term learning and research project at the intersection of actuarial science, statistics, programming, machine learning and AI.

## The philosophy

> Don't just consume knowledge. Produce evidence.

Every major concept we study should eventually result in something tangible:

- a mathematical derivation
- an experiment
- a model
- a dataset
- code
- a visualisation
- a research finding
- a documented lesson
- or a working software component

## What is ClaimSense?

ClaimSense is an experimental insurance claims intelligence and risk-modelling platform.

The long-term system may explore:

- claims frequency modelling
- claims severity modelling
- aggregate loss modelling
- Monte Carlo simulation
- actuarial pricing concepts
- reserving
- anomaly detection
- fraud detection
- machine learning
- natural language processing
- explainable AI
- portfolio risk
- VaR and CVaR
- stress testing

However, none of these components are assumed to be correct or necessary yet.

The project will evolve through research and experimentation.

## What makes this project different?

The objective is not simply to build an impressive-looking application.

The objective is to understand why the models work, when they fail, what their assumptions are, and whether they actually provide useful information.

## Starting point

This project begins on 17 August 2026.

The first task is not to build the application.

The first task is to define the problem properly.

## Initial Hypothesis

I currently believe that combining actuarial modelling with machine learning and AI could produce more useful insurance claims intelligence than relying on any one of these approaches independently.

This is a hypothesis, not a conclusion.

The project will attempt to test it.
